## 1. 프로젝트 개요

### 1.1 목적

TypeSafe AI의 **Jev(System One Model)** 를 사용해 VOC(Voice of Customer) 문의를 실시간으로 분류·판정하고, 그 결과에 따라 답변하거나 상담원에게 이관하는 웹 상담봇을 만든다.

토이 프로젝트이며, 목표는 두 가지다.

1. Jev의 실사용 감각(응답속도, confidence 신뢰도, 비용)을 직접 확인한다.
2. "판단은 Jev, 생성은 별도"라는 하이브리드 구조를 실제로 설계·검증한다.

### 1.2 반드시 전제할 것 — Jev는 텍스트를 생성하지 않는다

> Jev는 LLM이 아니다. 출력은 `choice` / `score` / `noul`(yes-no) 세 가지 타입의 **확률값**뿐이다.
> **고객에게 보낼 답변 문장을 Jev가 써주지 않는다.**

따라서 상담봇의 "말하는 부분"은 Jev 바깥에 따로 둔다. 이 문서 전체가 이 전제 위에서 쓰였다.

| 역할 | 담당 | 비고 |
|------|------|------|
| 의도 분류, 긴급도/불만도 판정, 이관 여부 결정 | **Jev** | 70~500ms, 비용 사실상 0 |
| 실제 답변 문장 | **FAQ 템플릿** (Phase 1) / **LLM** (Phase 2) | Phase 1은 LLM 없이 동작 |

### 1.3 기술 스택

| 구분 | 선택 | 사유 |

## 2. 범위

### 2.1 Phase 1 (이번 구현 범위)

- 고객이 문의를 입력하면 Jev가 **의도/긴급도/불만도/이관여부**를 판정
- 판정된 의도에 매핑된 **FAQ 템플릿 답변**을 반환
- `confidence`가 임계값 미만이면 **"상담원 연결" 분기**로 폴백
- Jev의 원시 판정 결과(probabilities, confidence)를 **인스펙터 패널**에서 시각화
- 처리된 문의를 **티켓 목록**에 누적 (인메모리 또는 로컬 스토리지)

### 2.2 Phase 2 (후속, 이번엔 구현 안 함)

- `confidence` 미달 케이스를 LLM(Claude)으로 넘겨 답변 생성
- 멀티턴 대화 맥락 유지
- DB 영속화, 관리자 통계 대시보드

### 2.3 명시적 제외 범위

- 실제 인증/회원가입 (익명 세션으로 처리)
- 실시간 상담원 채팅(웹소켓)
- 다국어 (한국어만)
- 파일 첨부

## 3. 사용자 시나리오

### 3.1 주 시나리오 — 자동 응답 성공

1. 고객이 채팅창에 "결제가 두 번 됐어요. 빨리 처리해주세요" 입력
2. 서버가 Jev 호출 → `intent: billing (confidence 0.91)`, `urgency: true`, `frustration: 2`
3. confidence가 임계값(0.70) 이상 → `billing` FAQ 템플릿 답변 출력
4. 긴급도 true → 답변 하단에 "우선 처리 요청됨" 배지 표시
5. 티켓 목록에 분류 결과와 함께 적재

### 3.2 분기 시나리오 — 확신 부족

1. 고객이 "그거 어떻게 하는 거였죠?" 같은 모호한 문의 입력
2. Jev 결과 `confidence 0.41`
3. 임계값 미달 → 템플릿 답변 대신 **되묻기 + 상담원 연결 버튼** 노출
4. 티켓은 `needs_human: true`로 적재

### 3.3 분기 시나리오 — 고불만 즉시 이관

1. 불만도 `score`가 최고 레벨로 판정
2. confidence와 무관하게 **즉시 상담원 이관 분기**
3. 티켓 우선순위 `high`로 적재

## 5. Jev 연동 명세

### 5.1 SDK 기본형 (공식 문서 확인됨)

```ts
import { choice, TypeSafeClient } from "@typesafe-ai/sdk";

const client = new TypeSafeClient(); // env: TYPESAFE_API_KEY

const response = await client.systemOne({
  state: { document: "I was charged twice. Please fix this ASAP." },
  questions: {
    category: choice("What is this ticket about?", {
      billing: null,
      technical: null,
      other: null,
    }),
  },
});

console.log(response.answers.category.choice);
```

> ⚠️ **구현 시 반드시 확인할 것**
> `choice()`의 시그니처는 위 예제로 확인됐으나, `score()` / `noul()`의 **JS 헬퍼 인자 형태는 공식 문서에서 확정하지 못했다.**
> `pnpm add @typesafe-ai/sdk` 후 `node_modules/@typesafe-ai/sdk` 의 `.d.ts` 타입 선언을 직접 읽어 확정할 것. 추측해서 작성하지 말 것.
> 참고로 Python SDK는 `Noul(instructions=..., criteria=NoulCriteria(true=..., false=...))`, `Score(instructions=..., criteria=[...])` 형태다.

### 5.2 질문 스키마 (4개를 1회 호출로 병렬 판정)

| key | 타입 | 목적 |
|-----|------|------|
| `intent` | `choice` | 문의 의도 분류 |
| `frustration` | `score` | 고객 불만 강도 (0~2) |
| `is_urgent` | `noul` | 시간 민감성 여부 |
| `needs_human` | `noul` | 사람 상담원이 필요한 성격인지 |

**`intent` criteria**

| 값 | 설명 |
|----|------|
| `billing` | 결제, 환불, 구독, 요금 관련 |
| `technical` | 오류, 버그, 연동 실패, 접속 문제 |
| `account` | 계정, 로그인, 비밀번호, 탈퇴 |
| `shipping` | 배송, 교환, 반품 |
| `etc` | 위 어디에도 속하지 않음 |

**`frustration` criteria (순서가 곧 0/1/2 레벨)**

| 레벨 | 설명 |
|------|------|
| 0 | 차분함. 사실만 서술 |
| 1 | 불만이 있으나 정중함 |
| 2 | 매우 화남. 강한 표현 사용 |

### 5.3 응답 형태 (공식 문서 확인됨)

```jsonc
// choice
{ "choice": "technical", "confidence": 0.78, "probabilities": { "technical": 0.85, "billing": 0.15, "sales": 0.0 } }
// score
{ "score": 1.0, "confidence": 1.0, "probabilities": { "0": 0.0, "1": 1.0, "2": 0.0 } }
// noul
{ "noul": 1.0 }
```

### 5.4 라우팅 정책 (비즈니스 로직 — UI와 분리할 것)

우선순위대로 평가하며, 먼저 걸리는 규칙이 이긴다.

| 순위 | 조건 | 결과 액션 |
|------|------|----------|
| 1 | Jev 호출 실패 / 타임아웃 | `ESCALATE` (안전 폴백) |
| 2 | `frustration.score >= 2` | `ESCALATE` (우선순위 high) |
| 3 | `needs_human.noul >= 0.5` | `ESCALATE` |
| 4 | `intent.confidence < 0.70` | `CLARIFY` (되묻기 + 상담원 버튼) |
| 5 | `intent.choice === 'etc'` | `CLARIFY` |
| 6 | 그 외 | `AUTO_REPLY` (FAQ 템플릿) |

`is_urgent`는 분기를 바꾸지 않고 **티켓 우선순위와 UI 배지**에만 영향을 준다.

임계값 `0.70`은 상수로 분리하고, 실측 후 조정 가능하게 둔다.

### 5.5 보안 / 운영 제약

- `TYPESAFE_API_KEY`는 **서버 전용**. `NEXT_PUBLIC_` 접두사 절대 금지.
- Jev 호출은 Route Handler(`app/api/voc/route.ts`)에서만 수행. 클라이언트에서 직접 호출 금지.
- Edge runtime 지원 여부가 공식 문서에 명시되지 않음 → Route Handler에 `export const runtime = 'nodejs'` 명시.
- Jev 호출 타임아웃 5초. 초과 시 `ESCALATE` 폴백.
- 입력 길이 상한 2,000자.

## 6. 데이터 모델

```ts
// entities/ticket
type Intent = 'billing' | 'technical' | 'account' | 'shipping' | 'etc';
type RouteAction = 'AUTO_REPLY' | 'CLARIFY' | 'ESCALATE';
type Priority = 'low' | 'normal' | 'high';

interface JevVerdict {
  intent: { choice: Intent; confidence: number; probabilities: Record<string, number> };
  frustration: { score: number; confidence: number };
  isUrgent: boolean;
  needsHuman: boolean;
  latencyMs: number;
}

interface Ticket {
  id: string;
  message: string;
  verdict: JevVerdict | null; // 호출 실패 시 null
  action: RouteAction;
  priority: Priority;
  reply: string | null;
  createdAt: string; // ISO
}
```
