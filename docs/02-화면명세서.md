## 1. FSD 폴더 구조

### 1.1 Next.js App Router와 FSD `pages` 레이어 이름 충돌 처리

FSD의 `pages` 레이어와 Next.js의 `app/` 라우팅이 충돌한다. 이 프로젝트는 **FSD `pages` 레이어를 `views`로 리네이밍**해서 해결한다.

```
jev-voc-bot/
├── app/                          # Next.js App Router — 라우팅 전용, 최대한 얇게
│   ├── layout.tsx
│   ├── page.tsx                  # → views/chat 을 렌더만
│   ├── tickets/page.tsx          # → views/tickets 을 렌더만
│   └── api/
│       └── voc/route.ts          # Jev 호출 (서버 전용, runtime = 'nodejs')
│
├── src/
│   ├── views/                    # FSD pages 레이어 (리네이밍)
│   │   ├── chat/
│   │   └── tickets/
│   │
│   ├── widgets/
│   │   ├── chat-panel/           # 채팅 영역 전체 조립
│   │   ├── verdict-inspector/    # Jev 판정 인스펙터 패널
│   │   └── ticket-table/
│   │
│   ├── features/
│   │   ├── send-inquiry/         # 문의 입력·전송
│   │   ├── escalate-to-human/    # 상담원 이관
│   │   └── reset-conversation/
│   │
│   ├── entities/
│   │   ├── message/              # 메시지 타입 + 버블 UI
│   │   ├── ticket/               # Ticket 타입, 우선순위 계산
│   │   └── verdict/              # JevVerdict 타입, confidence 해석, 라우팅 정책
│   │
│   └── shared/
│       ├── api/
│       │   ├── jev.server.ts     # TypeSafeClient 래퍼 (서버 전용)
│       │   ├── questions.ts      # choice/score/noul 질문 스키마 정의
│       │   └── voc.client.ts     # /api/voc 호출 (Axios)
│       ├── config/
│       │   ├── faq.ts            # 의도별 FAQ 템플릿
│       │   └── thresholds.ts     # CONFIDENCE_THRESHOLD = 0.70 등 상수
│       ├── lib/
│       └── ui/                   # Button, Badge, Spinner, ProbabilityBar
│
└── docs/
```

### 1.2 레이어 의존 규칙 (엄수)

```
app → views → widgets → features → entities → shared
```

- 위에서 아래로만 import 한다. 역방향 import 금지.
- 같은 레이어 내 슬라이스끼리 직접 import 금지 (필요하면 상위 레이어에서 조립).
- 각 슬라이스는 `index.ts`로 public API를 명시하고, 외부에서는 내부 경로를 직접 참조하지 않는다.

### 1.3 UI / 비즈니스 로직 분리 (엄수)

- **판정 해석·라우팅 결정·우선순위 계산은 전부 `entities/verdict`, `entities/ticket`의 순수 함수로 둔다.** 컴포넌트 안에서 `if (confidence < 0.7)` 같은 판단을 하지 않는다.
- 컴포넌트는 순수 함수의 결과를 받아 그리기만 한다.
- 이 분리 덕분에 라우팅 정책은 DOM 없이 단위 테스트가 가능해야 한다. (테스트 문서 TC-U-01~08)

## S-01. 상담 채팅 화면

### 레이아웃

```
┌──────────────────────────────────────────┬─────────────────────┐
│  Jev VOC 상담봇          [대화 초기화]   │  판정 인스펙터      │
├──────────────────────────────────────────┤  (S-02)             │
│                                          │                     │
│   ┌────────────────────────────┐         │  의도               │
│   │ 결제가 두 번 됐어요.       │ (고객)  │  ████████░░ billing │
│   │ 빨리 처리해주세요.         │         │  confidence 0.91    │
│   └────────────────────────────┘         │                     │
│                                          │  불만도  ██░░░  1   │
│   ┌────────────────────────────┐         │  긴급    ● YES      │
│   │ 🤖 중복 결제 확인을 도와   │ (봇)    │  이관필요 ○ NO      │
│   │ 드리겠습니다. ...          │         │                     │
│   │ [🔥 우선 처리 요청됨]      │         │  ⏱ 312ms           │
│   └────────────────────────────┘         │                     │
│                                          │                     │
├──────────────────────────────────────────┤                     │
│ [ 문의를 입력하세요...        ] [ 전송 ] │                     │
└──────────────────────────────────────────┴─────────────────────┘
```

### 구성 요소

| 요소 | 슬라이스 | 설명 |
|------|---------|------|
| 헤더 | `widgets/chat-panel` | 타이틀 + 대화 초기화 버튼 |
| 메시지 리스트 | `entities/message` | 역할별 버블(customer/bot/system) |
| 긴급 배지 | `shared/ui/Badge` | `isUrgent === true`일 때만 봇 답변 하단에 표시 |
| 이관 카드 | `features/escalate-to-human` | `action === 'ESCALATE'`일 때 버블 대신 노출 |
| 되묻기 카드 | `widgets/chat-panel` | `action === 'CLARIFY'`일 때 노출 |
| 입력 폼 | `features/send-inquiry` | React Hook Form + Yup |

### 액션별 봇 응답 UI

| `action` | 표시 내용 |
|----------|----------|
| `AUTO_REPLY` | FAQ 템플릿 답변 버블. `isUrgent`면 🔥 배지 동반 |
| `CLARIFY` | "조금 더 자세히 알려주시겠어요?" + 의도 후보 칩 2~3개 + [상담원 연결] 버튼 |
| `ESCALATE` | "상담원에게 연결해 드릴게요" 카드 + 접수번호 + [상담원 연결] 버튼 |

### 입력 폼 검증 (Yup)

| 규칙 | 메시지 |
|------|--------|
| 필수 | "문의 내용을 입력해주세요" |
| 최소 2자 | "2자 이상 입력해주세요" |
| 최대 2000자 | "2000자 이내로 입력해주세요" |

- 전송 중에는 입력창·버튼 `disabled`
- `Enter` 전송 / `Shift+Enter` 줄바꿈

### 상태별 화면

| 상태 | 표현 |
|------|------|
| 최초 진입 (Empty) | 봇 인사말 + 예시 문의 칩 3개 ("결제가 두 번 됐어요" 등) |
| 전송 중 (Loading) | 봇 자리에 타이핑 인디케이터, 인스펙터는 스켈레톤 |
| 성공 | 위 액션별 UI |
| API 에러 | 시스템 메시지 "일시적인 오류가 발생했어요. 상담원에게 연결해 드릴게요." + 이관 카드 (FR-09) |

### 접근성

- 메시지 리스트 컨테이너에 `aria-live="polite"`
- 새 메시지 추가 시 자동 하단 스크롤
- 전송 버튼 `aria-label="문의 전송"`

## S-02. 판정 인스펙터 패널

이 프로젝트의 핵심 관찰 지점. **Jev가 왜 그렇게 판단했는지**를 그대로 보여준다.

### 구성 요소

| 요소 | 설명 |
|------|------|
| 의도 확률 바 | `probabilities`의 모든 후보를 내림차순 막대로 표시. 선택된 값 강조 |
| confidence 게이지 | 0~1 수치 + 임계값(0.70) 마커를 함께 표시해 통과/미달이 한눈에 보이게 |
| 불만도 | 0/1/2 세그먼트 바 |
| 긴급 / 이관필요 | boolean 인디케이터 (● / ○) |
| 응답 시간 | `latencyMs` 표시 |
| 적용된 라우팅 규칙 | "규칙 4: confidence 미달 → CLARIFY" 처럼 **어느 규칙이 걸렸는지 문구로 노출** |

> 마지막 항목이 중요하다. 라우팅 정책 함수가 결과와 함께 `reason`을 반환하도록 설계하고, 패널은 그걸 렌더만 한다.

### 상태별 화면

| 상태 | 표현 |
|------|------|
| 판정 전 | "문의를 입력하면 Jev 판정 결과가 여기에 표시됩니다" |
| 로딩 | 스켈레톤 |
| 에러 | "판정 실패 — 안전 폴백으로 이관 처리됨" |

### 반응형

- `lg` 이상: 우측 고정 사이드 패널 (340px)
- `lg` 미만: 채팅 하단 접이식 아코디언. 기본 접힘, 헤더에 요약(`billing · 0.91`)만 표시

## S-03. 티켓 목록 화면

### 레이아웃

| 컬럼 | 내용 |
|------|------|
| 접수번호 | `Ticket.id` 앞 8자 |
| 문의 내용 | 1줄 말줄임 |
| 의도 | 배지 (의도별 색상) |
| confidence | 수치 + 임계값 미달 시 경고색 |
| 불만도 | 0/1/2 |
| 우선순위 | `high`는 강조 표시 |
| 처리 | `AUTO_REPLY` / `CLARIFY` / `ESCALATE` 배지 |
| 접수시각 | `HH:mm:ss` |

### 기능

- 우선순위 `high` 먼저, 그다음 최신순 정렬
- 처리 유형 필터 (전체 / 자동응답 / 되묻기 / 이관)
- 행 클릭 시 해당 티켓의 판정 상세 확장

### 상태별 화면

| 상태 | 표현 |
|------|------|
| Empty | "아직 접수된 문의가 없습니다" + [상담 시작하기] 링크 |
| 로딩 | 행 스켈레톤 3개 |

### 반응형

- `md` 미만: 테이블 대신 카드 리스트로 전환

## 3. 공통 UI 규칙

### 색상 토큰 (Tailwind 기준, 의미 단위로 정의)

| 용도 | 값 |
|------|-----|
| 자동응답 / 정상 | `emerald` 계열 |
| 되묻기 / 주의 | `amber` 계열 |
| 이관 / 위험 | `rose` 계열 |
| 중립 | `slate` 계열 |

- 하드코딩된 hex 금지. `shared/config` 또는 Tailwind 테마에 의미 이름으로 정의하고 참조한다.
- 다크모드는 Phase 1 범위 밖. 단 색상을 토큰으로 빼두어 나중에 붙일 수 있게 한다.

### 컴포넌트 작성 규칙

- 한 컴포넌트는 한 파일. 슬라이스 `index.ts`에 export 추가.
- `_buildXxx` 같은 private 빌드 함수로 UI를 쪼개지 말고, 별도 컴포넌트로 분리한다.
- 서버 컴포넌트를 기본으로 하고, 상태·이벤트가 필요한 곳에만 `'use client'`를 붙인다.

### 네이밍

- 컴포넌트: PascalCase / 함수·변수: camelCase / 상수: UPPER_SNAKE_CASE
- 파일: 컴포넌트는 PascalCase, 그 외는 kebab-case

## 4. API 계약

### `POST /api/voc`

**Request**

```json
{ "message": "결제가 두 번 됐어요. 빨리 처리해주세요" }
```

**Response 200**

```json
{
  "ticketId": "f3a91c08-...",
  "action": "AUTO_REPLY",
  "priority": "high",
  "reply": "중복 결제 확인을 도와드리겠습니다. ...",
  "reason": "규칙 6: 임계값 통과 → 자동응답",
  "verdict": {
    "intent": { "choice": "billing", "confidence": 0.91, "probabilities": { "billing": 0.91, "technical": 0.06, "account": 0.02, "shipping": 0.01, "etc": 0.0 } },
    "frustration": { "score": 1, "confidence": 0.88 },
    "isUrgent": true,
    "needsHuman": false,
    "latencyMs": 312
  }
}
```

**Response 400** — 입력 검증 실패

```json
{ "error": "INVALID_INPUT", "message": "2000자 이내로 입력해주세요" }
```

**Response 200 (Jev 장애 시 안전 폴백)**

> 장애를 5xx로 내보내지 않는다. 사용자 경험상 이관 분기로 정상 응답한다.

```json
{
  "ticketId": "...",
  "action": "ESCALATE",
  "priority": "normal",
  "reply": null,
  "reason": "규칙 1: Jev 호출 실패 → 안전 폴백",
  "verdict": null
}
```
