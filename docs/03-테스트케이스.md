# Jev VOC 상담봇 — 테스트 케이스 명세서

- **문서 버전**: v1.0
- **작성일**: 2026-09-21
- **선행 문서**: `01-기획명세서.md`, `02-화면명세서.md`

> **이 문서의 테스트는 구현과 동시에 반드시 작성한다.** 기능만 만들고 테스트를 미루지 않는다.

---

## 1. 테스트 전략

### 1.1 도구

| 레벨 | 도구 | 대상 |
|------|------|------|
| 단위 | Vitest | `entities`, `shared/lib`, `shared/config` 순수 함수 |
| 컴포넌트 | Vitest + React Testing Library | `entities/ui`, `features`, `widgets` |
| 통합 | Vitest + MSW | Route Handler ↔ 클라이언트, Jev SDK 모킹 |
| E2E | Playwright | 주요 사용자 플로우 |

### 1.2 원칙

- **Jev 실 API는 테스트에서 절대 호출하지 않는다.** 전부 MSW 또는 SDK 모듈 모킹으로 대체한다.
- 라우팅 정책은 **DOM 없이** 순수 함수 단위 테스트로 전부 커버한다. 이게 안 되면 UI/로직 분리가 실패한 것이므로 설계를 고친다.
- 테스트 파일은 대상과 같은 슬라이스 안에 둔다. (`entities/verdict/lib/route-policy.test.ts`)
- 테스트 이름은 한국어로, 기대 동작을 서술형으로 쓴다.

### 1.3 커버리지 기준

| 대상 | 기준 |
|------|------|
| `entities/verdict`, `entities/ticket` (라우팅·우선순위 로직) | **100%** — 예외 없음 |
| Route Handler | 분기 전부 |
| 그 외 | line 80% 이상 |

## 2. 단위 테스트 — 라우팅 정책 (`entities/verdict`)

대상: `resolveAction(verdict | null): { action, priority, reason }`

> 규칙 우선순위는 `01-기획명세서.md` 5.4 참조. **먼저 걸리는 규칙이 이긴다**는 성질을 반드시 테스트한다.

| ID | 케이스 | 입력 | 기대 결과 |
|----|--------|------|----------|
| TC-U-01 | Jev 호출 실패 | `verdict === null` | `ESCALATE`, priority `normal`, reason에 "규칙 1" |
| TC-U-02 | 불만도 최고 → 즉시 이관 | `frustration.score = 2`, `confidence 0.99` | `ESCALATE`, priority **`high`** |
| TC-U-03 | 불만도 최고가 confidence를 이긴다 | `frustration.score = 2`, `intent.confidence 0.99` | `AUTO_REPLY`가 아니라 `ESCALATE` |
| TC-U-04 | 사람 필요 판정 | `needsHuman = true`, `confidence 0.95` | `ESCALATE` |
| TC-U-05 | confidence 미달 | `intent.confidence = 0.69` | `CLARIFY` |
| TC-U-06 | confidence 경계값 (임계값과 동일) | `intent.confidence = 0.70` | `AUTO_REPLY` (이상이면 통과) |
| TC-U-07 | 의도가 etc | `choice = 'etc'`, `confidence 0.95` | `CLARIFY` |
| TC-U-08 | 정상 자동응답 | `billing`, `0.91`, `frustration 1` | `AUTO_REPLY` |
| TC-U-09 | 긴급은 분기를 바꾸지 않는다 | `isUrgent = true`, `confidence 0.91` | `AUTO_REPLY` 유지 |
| TC-U-10 | 긴급은 우선순위만 올린다 | `isUrgent = true`, `AUTO_REPLY` | priority `high` |
| TC-U-11 | reason 문구 반환 | 임의 입력 | `reason`이 비어있지 않고 적용된 규칙 번호를 포함 |

### 경계값 / 방어 테스트

| ID | 케이스 | 기대 결과 |
|----|--------|----------|
| TC-U-12 | `confidence = 0` | `CLARIFY` |
| TC-U-13 | `confidence = 1` | `AUTO_REPLY` |
| TC-U-14 | `probabilities`가 빈 객체 | 예외를 던지지 않고 `CLARIFY`로 폴백 |
| TC-U-15 | 알 수 없는 intent 값 수신 | 예외 없이 `CLARIFY`로 폴백 |

## 8. 실행 명령어

```bash
pnpm test              # Vitest watch
pnpm test:run          # 1회 실행 (CI)
pnpm test:coverage     # 커버리지
pnpm test:e2e          # Playwright
pnpm type-check        # tsc --noEmit
```
